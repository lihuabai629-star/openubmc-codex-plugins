# 结构元素中的标点
## 6.1 标题
- [ ] 中文标题不以"。"或"："结尾
- [ ] 英文标题不以"."或":"结尾
- [ ] 所有标题末尾不加标点（问号除外）
- [ ] **[SUGGESTION]** 英文标题使用 sentence case，推荐 3-11 个词（FAQ、Overview 等公认短标题除外）
## 6.2 列表
- [ ] 列表内标点须一致：全部加句号或全部不加，不能混用（属于标点一致性错误，必须修复）
- [ ] 专项规则：操作步骤类列表（包含动作描述的步骤项）无论中英文，全部以对应语言的句号结尾
  - 中文操作步骤项以全角句号「。」结尾
  - 英文操作步骤项以半角句号「.」结尾
- [ ] 通用规则：
  - 完整陈述句列表项必须加句号
  - 仅纯名词/属性类无动作的短语列表可以不加句号，如功能特性列举、配置项说明等
- [ ] 列表项首字母大写（英文）/首字规范（中文）
- [ ] 中文列表引导句以全角冒号「：」结尾
- [ ] 英文列表引导句以半角冒号「:」结尾
### 操作步骤类的判定条件（必须按以下条件机械判定，不可凭语义直觉）：
| 列表项模式 | 判定结果 | 是否加句号 | 示例 |
|---|---|---|---|
| 有序列表项（`1.` `2.` `3.` 等） | 操作步骤 | 强制加句号 | `1. 访问下载链接。` |
| 无序列表项（`-`）且包含任意及物操作动词 | 操作步骤 | 强制加句号 | `- 下载安装包到本地。` |
| 无序列表项（`-`）且以"（方式X）"开头 | 操作步骤 | 强制加句号 | `- （方式一）直接下载 GPG 文件安装。` |
| 无序列表项（`-`）且为说明/描述性完整句 | 非操作步骤 | 完整句加句号 | `- 如果您使用的不是 wsl 系统，需要在浏览器中手动输入该地址（视您的系统环境而定）。` |
| 无序列表项（`-`）且为纯名词/属性短语 | 非操作步骤 | 不加句号 | `- **操作系统**：Windows 10 或更高版本` |
### 6.2.1 列表项判定决策树（v3.1新增，强制按顺序执行，先匹配先停）
⚠️ 多模型测试中，6.2规则的命中数从0到4波动。v3.1引入决策树，禁止模型基于"语义推断"判定：
```
判定顺序（自上而下，先匹配先停止）：
【步骤1】检查列表项末尾字符
  ├─ 末尾字符 ∈ {。, ., !, ?, ！, ？} → 通过（已加句号）
  └─ 末尾字符 ∈ {:, ：} → 进入步骤2
【步骤2】冒号结尾的特殊处理
  ├─ 下一行存在缩进子内容（子列表项/代码块/图片） → 通过（引导子内容，冒号保留）
  └─ 下一行无缩进子内容 → 进入步骤3
【步骤3】判定列表类型
  ├─ 有序列表（`数字.`） → 必须以 。 结尾，否则报错（命中条件：ordered_list）
  ├─ 无序列表项（`-`）且以"（方式X）"或"Optional:"开头 → 必须以 。 结尾（命中条件：way_prefix）
  ├─ 无序列表项（`-`）且文本经过操作动词grep命中 → 必须以 。 结尾（命中条件：action_verb，必须列出匹配动词）
  ├─ 无序列表项（`-`）且为完整句（含主谓宾结构，且长度 ≥ 10字符） → 必须以 。 结尾（命中条件：full_sentence）
  └─ 其余（纯名词短语、属性短语） → 不加句号（命中条件：noun_phrase）
```
#### 报告强制要求：
- 报告中每个6.2命中必须标注：`命中条件编号 + 命中动词`
- 示例：`第90行 命中条件3-action_verb（动词：复制保存） → 应加句号`
- 严禁基于"语义推断"判定，命中条件必须从决策树中明确选择一项
> 操作动词清单统一见1.7.4节，保持规则判定一致性
## 6.3 简短描述和摘要
- [ ] 简短描述和摘要必须是完整句子，不能以冒号结尾
- [ ] 简短描述不能顺延到下方的列表或块；不使用"以下"/"the following"等前向引用
## 6.4 表格与图片
- [ ] 表格/图片标题末尾不加句号（中文"。"和英文"."均不加）
- [ ] 英文表格标题使用 sentence case
- [ ] 中文表格标题规范表述
## 6.5 块标题（v3.1强制grep匹配，禁止漏检）
- [ ] 块标题末尾禁止以冒号/句号结尾（问号除外），符合以下任意特征的全部判定为块标题，强制执行：
  - 以`> **`开头的说明/备注类标题，如`> **说明**：`
  - 以`**`开头加粗的属性标题，如`**参数**：`
  - GitHub Alert类标题，如`> [!NOTE]说明：`、`> [!TIP]提示：`
  - 列表引导句，如`支持以下操作系统：`、`需要准备的依赖：`
  - 表格表头属性说明，如`| 参数 | 说明 |`的"说明"后无需冒号
### 6.5.1 强制grep匹配模式（v3.1新增，杜绝漏检）
⚠️ 多模型测试中，A-31模型漏检了7处块标题（仅识别出2处，应识别9处）。v3.1要求：执行6.5规则时，**必须运行1.8脚本的 `scan_block_titles()` 函数**，对每条命中行报错。匹配模式如下：
| 编号 | 正则模式 | 适用场景 | 示例 |
|------|----------|----------|------|
| 模式1 | `^\s*>\s*(?:!\[.*?\]\([^)]*\)\s*)?\*\*[^*]+[:\uff1a]\*\*` | Markdown引用块加粗标题以冒号结尾（含可选图标前缀，允许行首缩进） | `> **说明：**`、`> ![](icon.gif) **说明：**`、`    > **说明：**`（嵌套） |
| 模式2 | `^\s*>\s*\!\[.*\]\(.*\)\s*\*\*[^*]+[:\uff1a]\*\*` | 仅含图标的块标题（模式1的子集，单独保留以便审计） | `> ![icon](path) **说明：**` |
| 模式3 | `^\s*>\s*\[!\w+\][^*]*[:\uff1a]` | GitHub Alert 块标题（允许行首缩进） | `> [!NOTE]说明：`、`> [!TIP]提示：` |
| 模式4 | `^\s*\*\*[^*]+[:\uff1a]\*\*\s*$` | 独立行加粗块标题 | `**参数：**`、`**返回值：**` |
#### 强制要求：
- **每条命中独立计数，禁止合并**（即使9处相同的`> **说明：**`，也必须独立计数为9个问题）
- 报告中每个6.5命中必须标注：`命中模式编号 + 完整原文`
- 报告frontmatter中`prescan_raw.block_title_hits_6_5`字段必须列出所有命中行号
- 强制执行校验清单中"已使用脚本/grep验证6.5块标题命中数 = 实际匹配行数"必须打勾
> 与1.9.4联动：本规则与1.9.4【明确包含场景】保持一致，禁止豁免任何符合4个模式的命中行。
