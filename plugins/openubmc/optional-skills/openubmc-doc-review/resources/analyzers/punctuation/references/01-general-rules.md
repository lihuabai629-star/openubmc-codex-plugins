# 通用规则
## 1.1 语言判定原则
- [ ] 根据句子主体语言决定标点风格：中文句子使用中文标点，英文句子使用英文标点
  - 中文句子："请先安装 Python 3.12，然后配置环境变量。"
  - 英文句子："Install Python 3.12, then configure the environment variables."
- [ ] 无法判定时，以句末标点所属语言体系为准
## 1.2 豁免区域
- [ ] 代码块和行内代码中的标点不受文档标点规则约束；但中文全角标点意外混入代码会导致语法错误或运行异常，属于高严重度问题，须专项检查。
- [ ] 反引号包裹的内联代码（如 `` `git commit -m "message"` ``）中的标点自动豁免；未包裹反引号的命令行片段不豁免
- [ ] URL中的标点（/ : . ? = &）不受文档标点规则约束
- [ ] 文件路径中的标点（/ \ .）不受文档标点规则约束
- [ ] 命令行语法中的标点不受文档标点规则约束
- [ ] Markdown表格中与 `|` 相邻的空格不报错
- [ ] Markdown扩展语法（如连续三个冒号 `:::` 表示GitHub Alerts）不报错
- [ ] 被中文引号 `""` 包裹的标点符号不做连续标点检查
- [ ] 英文句号 `.` 后跟空格/斜杠/英文字母时不做混用检查（如URL、版本号 `v1.0`）
### 1.2.1 代码块中文标点混入检查
代码块和行内代码不受文档标点规则约束（见1.2），但中文全角标点意外混入代码会导致语法错误或运行异常，属于高严重度问题，须专项检查。
- [ ] 代码块和行内代码的**代码部分**不应出现中文全角标点符号，包括：
  ```
  ， 。 ； ： ！ ？ （ ） 【 】 《 》 " " ' ' — … 、 ～
  ```
- [ ] 常见混入场景及修复：
  - 中文句号 `。` 替代英文句号 `.`：
    - 正确：`import module.submodule`
    - 错误：`import module。submodule`
  - 中文逗号 `，` 替代英文逗号 `,`：
    - 正确：`func(a, b)`
    - 错误：`func(a， b)`
  - 中文分号 `；` 替代英文分号 `;`：
    - 正确：`int ret = 0;`
    - 错误：`int ret = 0；`
  - 中文冒号 `：` 替代英文冒号 `:`：
    - 正确：`stream(stream):`
    - 错误：`stream(stream)：`
  - 全角括号 `（` `）` 替代半角括号 `(` `)`：
    - 正确：`super().__init__()`
    - 错误：`super().__init__(）`
- [ ] 代码块内的**中文注释**中使用中文标点是合法的，不报错
  - 正确：`# 初始化参数，设置默认值。`
  - 错误：`x = func(a， b)`（代码部分使用了中文逗号）
- [ ] 代码块内的**字符串字面量**中使用中文标点是合法的，不报错
  - 正确：`print("你好，世界")`
  - 错误：`result = calc(x， y)`（代码部分使用了中文逗号）
- [ ] 此规则的严重等级为 **required**（代码无法运行，影响远大于排版问题）
## 1.3 标点符号参考集
**常用中文标点符号**：
```

```
**所有中文标点符号**：
```

```
**常用英文标点符号**：
```
. ? ! , ; : " ' ( )
```
**所有英文标点符号**：
```
! " # $ % & ' ( ) * + , - . / : ; < = > ? @ [ ] ^ _ ` { | } ~
```

| 「   | 」   | 中文 |
| 『   | 』   | 中文 |
| （   | ）   | 中文 |
| 【   | 】   | 中文 |
| 《   | 》   | 中文 |
| 〈   | 〉   | 中文 |
| "   | "   | 中文 |
| '   | '   | 中文 |
| \[  | ]   | 英文 |
| {   | }   | 英文 |

**英文引号配对说明**：英文直双引号 `"` 和直单引号 `'` 是同一字符既做开符号又做闭符号，无法使用栈算法直接配对。配对检查方法：
- 统计同一文本段中同种引号的出现次数，奇数则报错（未闭合）
- 或结合上下文判断：引号前为空格/标点/句首时为开引号，引号后为空格/标点/句末时为闭引号
## 1.5 归类优先原则（必须严格执行，避免重复计数）
⚠️ 当同一问题可归入多条规则时，按以下优先级**唯一归类**，禁止同一问题归入多个规则，避免重复计数或归类不一致：
| 优先级 | 问题类型 | 唯一归属规则 | 典型示例 |
|--------|----------|--------------|----------|
| 1 | 列表项标点相关问题（末尾缺句号、列表引导句冒号错误等） | 规则 6.2 | 有序列表项末尾缺句号 → 归入6.2，不归入3.1/2.8 |
| 2 | 章节名/标题误用书名号/引号问题 | 规则 3.9 | 章节名用《》包裹 → 归入3.9，不归入3.8/6.1 |
| 3 | 中文标点前后多余空格问题 | 规则 5.1 | 中文逗号前有空格 → 归入5.1，不归入4.1 |
| 4 | 中文与英文/数字之间缺空格/空格不一致问题 | 规则 4.1 | `openEuler系统`缺空格 → 归入4.1，不归入5.1 |
| 5 | 并列项标点错误（顿号/逗号混用、最后一项用顿号等） | 规则 3.3 | `Python、Go、Java`最后一项用顿号 → 归入3.3，不归入3.2 |
| 6 | 数值范围标点错误 | 规则 3.7 | 数值范围用英文短横线 → 归入3.7，不归入2.3 |
| 7 | 成对标点配对错误（引号/括号不闭合、不匹配等） | 规则 5.3 | `（xxx)`半角闭括号 → 归入5.3，不归入3.10 |
> 注意：若存在多规则叠加的情况，按最高优先级的规则归类，其余规则自动跳过，不得重复计数
## 1.6 边界条件判定表（强制执行，消除规则歧义）
⚠️ 以下边界条件在多模型测试中产生了严重分歧，必须严格按照本表的确定性判定执行，不得自行推断：
### 1.6.1 4.1基准判定的完整区间表（v3.1新增，覆盖所有占比区间）
**第一步：判定文档是否为技术文档**
满足以下任一条件即为「技术文档」：
- 文档包含Markdown代码块（``` 或 ~~~ 包裹）
- 文档包含行内代码（` 包裹）≥ 3 处
- 英文标识符（变量名、函数名、命令、API、产品名）密度 ≥ 5%
- 文档包含技术关键词：`install`、`config`、`API`、`SDK`、`Docker`、`Linux`、`Windows`、`Kubernetes`、`Python`、`Go`、`JavaScript`、`版本`、`配置`、`部署`、`命令` 等任一
**第二步：按完整区间表判定基准（取代旧的"≥80%/40-60%"两段式）**
| 无空格占比 | 通用文档基准 | 技术文档基准 | 说明 |
|------------|-------------|-------------|------|
| ≥ 80% | 不加空格 | **加空格（强制兜底）** | 即使统计无空格占多数，技术文档仍按行业事实标准 |
| 60% - 80% | **不加空格（主流派优先）** | **加空格（强制兜底）** | 新增灰色区间裁决 |
| 40% - 60% | 加空格（默认推荐） | 加空格 | 无明确多数时统一加空格 |
| 20% - 40% | 加空格 | 加空格 | — |
| < 20% | 加空格 | 加空格 | — |
**第三步：强制兜底规则**
- 技术文档无论统计结果如何，基准强制为「加空格」——避免出现"建议把规范写法改成不规范写法"的尴尬
- 兜底规则的依据：业界标准（中文文案排版指北、Microsoft风格指南、Google中文风格指南）均推荐技术文档中中英文之间加空格
### 1.6.2 其他边界条件判定表
| 规则 | 模糊场景 | 确定性判定 | 禁止行为 |
|------|----------|------------|----------|
| 4.1 | 修复方向是加空格还是删空格 | 以1.6.1完整区间表判定结果为准：若基准为「加空格」，则判定"无空格的位置违规"（修复：加空格）；若基准为「不加空格」，则判定"有空格的位置违规"（修复：删空格） | 禁止不按基准表直接决定修复方向 |
| 3.8 | 如何区分中文全角引号""和英文半角引号"" | **必须通过预扫描（见1.7+1.8）识别引号Unicode码点**：U+201C/U+201D=中文全角引号（合法）；U+0022=英文直引号（中文语境下违规）；U+0027=英文直单引号（中文语境下违规）；U+2018/U+2019=中文全角单引号（合法） | 禁止凭视觉判断引号类型，必须依据预扫描结果 |
| 3.9 | `《[链接文本](url)）》`中的书名号是独立文档还是章节名 | **按链接目标判定**：链接指向独立文件（如`env_introduction.md`、`ubuntu_env.md`）=独立文档→书名号合法（Suggestion建议加）；链接指向同文档锚点（如`#section`）=章节名→书名号违规（Required） | 禁止不查看链接目标直接判定 |
| 3.9 | 章节名被引号""包裹 | 章节名/模块名使用引号包裹属于3.9范畴（章节名禁止使用书名号/引号标记），归入3.9，严重等级为Required | 禁止将此类问题归入3.8 |
| 6.2 | 列表项以冒号结尾且引导子列表（如`- 启动 BMC Studio：`后跟代码块或子列表） | **冒号引导子列表/代码块时，冒号保留，该列表项不归入6.2的句号检查范围**。判定条件：该列表项以冒号结尾，且下一行存在缩进的子内容（子列表项、代码块、图片等） | 禁止将冒号替换为句号（破坏引导关系）；禁止在冒号后追加句号产生"：。" |
| 6.2 | 列表引导句以冒号结尾（如`2. 根据安装向导提示进行操作：`） | **引导句以冒号结尾且后续跟子列表时，冒号保留，不添加句号**。判定条件同上：下一行存在缩进的子内容 | 禁止产生"：。"的修复建议 |
| 6.5 | `> **说明**：<br>` 中的冒号是否违规 | `<br>`是HTML标签，不视为标点。冒号仍为块标题末尾标点，**应删除**：`> **说明**<br>` | 禁止因`<br>`的存在而跳过冒号检查 |
| 3.7 | "步骤 2-步骤 5"中的连字符`-` | 中文语境中"数字/步骤+连字符+数字/步骤"=数值范围错误，**必须用"～"替换**：`步骤 2～步骤 5`。此规则不因连字符出现在代码块附近的说明文字中而豁免 | 禁止将此场景误判为英文语境或合法连字符用法 |
| 6.5 | `> [!NOTE]说明：` 中的冒号 | GitHub Alert类块标题末尾冒号**应删除**：`> [!NOTE]说明` | 禁止跳过此类块标题的冒号检查 |
## 1.7 字符级预扫描规范（感知层与判断层分离架构）
⚠️ 本节是v3.0的核心改进，旨在将"字符识别与模式匹配"（感知层）与"规则判定"（判断层）分离，减少模型对Unicode字符识别和全文统计的依赖。
**架构原则**：
- **感知层**（Perception）：通过确定性字符扫描，输出结构化标记数据，不依赖模型理解能力
- **判断层**（Judgment）：基于感知层输出的标记数据，应用规则进行判定，依赖模型的语义理解能力
- 禁止判断层绕过感知层直接扫描原始文本进行字符级判定
**预扫描执行时机**：在步骤1（语言判定）完成后、步骤2（逐规则扫描）开始前执行
**预扫描必须输出的结构化数据**（以下5项必须全部完成，缺一不可）：
### 1.7.1 引号字符Unicode识别
对文档全文（排除代码块和行内代码）执行以下扫描，输出每个引号字符的位置和Unicode码点：
```
扫描规则：
- U+0022 (") → 标记为"英文直双引号"
- U+0027 (') → 标记为"英文直单引号"
- U+201C (") → 标记为"中文左弯引号"
- U+201D (") → 标记为"中文右弯引号"
- U+2018 (') → 标记为"中文左弯单引号"
- U+2019 (') → 标记为"中文右弯单引号"
- U+300C (「) → 标记为"直角左引号"
- U+300D (」) → 标记为"直角右引号"
输出格式：
| 行号 | 列号 | 字符 | Unicode码点 | 标记类型 |
```
### 1.7.2 中英文相邻空格统计
对文档全文（排除代码块、行内代码、URL、文件路径）执行以下扫描：

| 行号 | 原文片段 | 当前状态 | 与基准一致性 |
```
### 1.7.3 列表项结构标记
对文档全文执行以下扫描，标记所有列表项的结构特征：

扫描规则：
- 匹配以`\s*(\d+\.|-)\s`开头的行

## 1.8 强制脚本化预扫描（v3.2核心架构）
⚠️ **本节是 v3.2 整个判定层的实现**。所有规则的命中位置、命中规则编号、命中等级全部由本脚本输出决定，模型不得自行判定。
**v3.2 相比 v3.1 的核心改进**：
- 脚本从覆盖 7 个字段扩展为覆盖 **13 条机械可判定规则**，新增 6 个扫描函数：
  - `scan_trailing_whitespace` — 5.1 行末多余空格
  - `scan_punct_with_space` — 5.1 中文标点前后多余空格
  - `scan_halfwidth_paren_with_zh` — 3.10 半角括号含中文
  - `scan_dunhao_list_end` — 3.3 顿号末尾未用"和/或/等"
  - `scan_range_hyphen` — 3.7 中文语境数值范围半角连字符
  - `scan_list_violations` — 6.2 列表项决策树（完全机械化）
- 脚本输出一个**标准化违规清单 `violations`**（数组），每条违规含 `lineno`/`rule`/`severity`/`condition`/`matched_text`/`confidence`/`suggestion_hint` 字段
- 模型直接根据 `violations` 数组渲染报告，1:1 映射
**强制要求**：
- 在步骤 1.8 必须生成并运行本节标准 Python 脚本（不得修改判定逻辑，仅可优化代码风格）
- 脚本输出的 JSON 为后续报告生成的**唯一依据**
- 禁止模型自行"目测"统计或自行新增违规
- 报告 frontmatter 中必须粘贴脚本输出的完整 JSON（字段名 `prescan_raw`）
**标准预扫描脚本调用方式（v3.3：脚本已独立存放于 scripts/prescan.py）**：

## 1.9 明确豁免与包含清单（v3.1新增，消除范围归属歧义）
⚠️ 多模型测试中，"图 2 描述文字"、"路径分隔顿号"、"Markdown链接边界"等corner case的归属在不同模型间剧烈波动。v3.1明确列举如下：
### 1.9.1 4.1 规则的明确豁免场景（不计入统计、不报错）
- **图表标题中的编号空格**：`**图 2** 描述文字`、`**表 2** 描述文字`、`**Figure 1** Description`
  - 理由：`图 N`/`表 N` 是固定排版模式，内部空格属于版式而非中英空格
- **Markdown链接标记 `[]()` 与中文边界**：`参考[文档](url)的说明`
  - 理由：链接是结构性元素，边界视为不可见
- **加粗/斜体标记 `**` `*` 与中英边界**：`**强调**说明`、`*emphasis*中文`
  - 理由：标记符号属于Markdown语法元素，不参与文本流空格判定
- **HTML标签内部**：`<a name="...">` 内的空格、`<br>` 前后的空格
- **引号内引用的原文**（英文UI字符串、命令、错误消息）前后：`按"Enter"键无响应`
  - 理由：引号包裹的原文不可修改
### 1.9.2 4.1 规则的明确包含场景（必须计入统计、必须报错）
- 普通正文中"中文字符 + 英文单词"：如`使用openEuler操作系统`
- 中文 + 数字：`不小于4GB`（注意：数字单位归3.13，中文与数字归4.1，两者可同时计数）
- 中文 + 英文标识符：`若为AArch64架构`、`服务器BIOS内置NVMe`
- 中文 + 英文产品名：`安装Kubernetes部署`、`使用Docker容器`
### 1.9.3 3.3 顿号规则的明确豁免场景
- **路径分隔**：`/var/log、/var/log/audit、/home、/tmp` 中的最后一个顿号
  - 理由：路径列表是数据结构性枚举，不适用"最后一项用'和'"的中文语法规则
- **配置项/参数名并列**：`--flag1、--flag2、--flag3` 中的最后一个顿号
- **代码标识符并列**（用反引号包裹）：``` `qemu`、`libvirt`、`edk2` ```
  - 注意：未用反引号的纯英文标识符并列（如`qemu、libvirt、edk2`）仍违规，应改用半角逗号
### 1.9.4 6.5 块标题规则的明确包含场景（必须grep匹配，不得遗漏）
- `> **说明：**` / `> **注意：**` / `> **须知：**` / `> **警告：**` / `> **提示：**`
- `> ![](.../icon.gif) **说明：**`（图标在前的引用块标题）
- `> [!NOTE]说明：` / `> [!TIP]提示：` / `> [!WARNING]警告：`（GitHub Alert）
- `**参数：**` / `**输入：**` / `**返回值：**`（独立行加粗块标题）
**强制要求**：执行6.5规则时，必须运行1.8脚本的 `scan_block_titles()` 函数，**对每条命中独立计数，禁止合并**。
