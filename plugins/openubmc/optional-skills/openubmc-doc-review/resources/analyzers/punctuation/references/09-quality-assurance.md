# 质量保障机制（doc-punctuation-tester）

本文件定义技能的版本管理、标准测试用例集、差异对比规则和模型间一致性基线。

## 10.1 版本管理规则

- 本技能每次更新迭代都升级版本号，格式为`主版本号.次版本号.修订号`
- **主版本号升级**：规则发生重大变更，影响判定结果一致性
- **次版本号升级**：新增规则或修改规则判定逻辑
- **修订号升级**：修复文档错误、优化描述，不影响判定结果
- v3.0为次版本号升级（新增预扫描架构、边界条件判定表、交叉验证步骤），影响判定结果一致性
- 所有检测报告必须在审查依据字段中标注使用的技能版本号，便于追溯差异原因
- 版本升级后必须重新运行标准测试用例集，验证结果在预期范围内方可发布

## 10.2 标准测试用例集（用于验证技能执行一致性）

每次技能更新后、每次检测完成后，必须使用以下标准测试用例验证输出结果，确保一致性：

| 测试用例文档类型 | 预期问题数量范围 | 预期最低得分范围 |
|--------------|--------------|--------------|
| 标准中文文档 | 15±2 | 4.5±1 |
| 标准中英混合文档 | 20±2 | 3.5±1 |
| 标准英文文档 | 12±2 | 6.0±1 |

若验证结果超出预期范围，必须排查规则执行是否有遗漏或错误，不得直接输出报告。

**测试用例文档示例模板**：

```markdown
# 标准中文测试文档（示例）

1. 点击"保存"按钮
2. 请输入用户名和密码，点击登录

（完整测试文档含50+行，覆盖所有规则的典型场景）
```

## 10.3 差异对比规则

若同一文档两次检测结果不一致，按以下优先级排查原因：

1. 是否使用了不同版本的技能
2. 是否完整执行了所有步骤，特别是完整性自检二次扫描
3. 是否有规则理解不一致的情况，以SKILL文档描述为准
4. 若规则描述模糊，按"更严格"原则判定
5. 是否正确执行了步骤1.8预扫描和步骤5.5交叉验证
6. 若两次检测结果差异超过5个问题，必须启动正式差异排查流程，输出差异分析报告

## 10.4 问题编号规则

所有检测出的问题必须按以下规则编号，确保可追溯：

- Required类问题：R+序号（从1开始递增）
- Suggestion类问题：S+序号（从1开始递增）
- 每个问题必须关联对应的规则ID，如规则6.2、规则3.9等

## 10.5 模型间一致性基线（v3.4 重大改写）

⚠️ **v3.4 的核心改进**：通过 violations_confirmed / violations_pending_review 的结构性拆分 + review_decision 强制填写，从架构上确保模型执行复核步骤。

### 10.5.1 v3.4 关键规则的严格相等要求

| 规则 | 不同模型间的期望关系 | 偏离时的处理 |
|------|---------------------|--------------|
| violations_confirmed 数量 | **5 个模型必须 100% 相同** | 偏离即说明脚本未正确执行 |
| violations_pending_review 数量 | **5 个模型必须 100% 相同** | 同上 |
| pending_review 复核结果（keep/exempt） | 允许 ±2 条差异 | 语义判断边界可接受微小差异 |
| 6.5（块标题冒号）confirmed 命中数 | 100% 相同 | 偏离即说明脚本未正确执行 |
| 6.2（列表缺句号）confirmed 命中数 | 100% 相同 | 同上 |
| 3.13（数字单位）confirmed 命中数 | 100% 相同 | 同上 |
| 3.10（半角括号含中文）confirmed 命中数 | 100% 相同 | 同上 |
| 3.3（顿号末尾）pending_review 命中数 | 100% 相同，复核结果 ±2 | — |
| 3.1（句号）pending_review 命中数 | 100% 相同，复核结果 ±2 | — |
| 5.1（标点空格 / 行末空格）confirmed 命中数 | 100% 相同 | 同上 |
| 4.1（中英空格）confirmed 命中数 | 100% 相同 | 同上 |
| 3.8（引号）confirmed 命中数 | 100% 相同 | 同上 |

### 10.5.2 唯一允许差异的规则

| 规则 | 允许差异范围 | 原因 |
|------|--------------|------|
| 3.9（书名号 Suggestion） | ±2 处 | 量化触发条件含语义判断 |
| pending_review 复核结果 | ±2 处 | 语义判断边界微小差异 |

### 10.5.3 v3.4 报告级别的强制要求

- 报告 traceability_stats 中的 `violations_confirmed` 数量必须 = **脚本输出的 `violations_confirmed`** 中条目数量
- 报告 traceability_stats 中的 `pending_review_completion_rate` 必须为 "100%"
- 报告"confidence:medium复核记录"段落中每条 pending_review 的 `review_decision` 不得为 null
- 以上三项任一不满足，报告视为无效

### 10.5.4 预期总问题数范围（v3.4）

| 文档类型 | 5 模型间预期波动 |
|----------|----------------|
| 任意类型 | **±5% 波动**（confirmed 一致 + pending_review 复核差异 ±2） |

### 10.5.5 模型间一致性目标对比

- **v3.0**：±2.1 倍波动（23-49）
- **v3.1**：±1.6 倍波动（28-45）
- **v3.2/v3.3**：±5% 波动预期，但实际可达 ±48 条（因 medium 复核可被跳过）
- **v3.4 目标**：±5% 波动（如 46-50），复核不可跳过
