# 外部链接检测策略

## 分层检测流程

外部链接检测分为两个阶段：

**阶段一：静态模式匹配**（离线，全部执行）
1. 提取所有外部链接的完整 URL 字符串
2. 用域名/协议拼写错误正则表匹配 → 命中则直接报 L1 Error（无需联网）
3. 用白名单过滤占位符/本地地址/示例域名
4. 剩下无法静态判断的 URL → 进入阶段二

**阶段二：HTTP 可达性验证**（在线，可选执行）
1. **请求方式** — 优先发送 HEAD 请求（5s 超时），若 HEAD 返回 ≥ 400，降级为 GET 请求再次验证
2. **代码托管平台特殊处理** — GitCode/AtomGit 的 `blob` 链接自动转为 `raw` 链接再请求
3. **重试策略** — 网络异常累计重试最多 3 次，超过后标记为超时
4. **结果缓存** — 同一 URL 结果应缓存，避免重复请求
5. **状态码判定**：

## 状态码判定

| 状态码范围 | 判定 | 严重级别 |
|-----------|------|---------|
| 100-399 | 有效 | — |
| 401 | 需要认证 | Warning（非公开资源） |
| 403 | 访问被拒绝 | Warning（可能需登录或 IP 受限，非一定无效） |
| 404 | 无效 | Error |
| 429（限流） | 暂时不可用 | 重试后仍失败则 Warning |
| 499（超时） | 不确定 | Warning |
| 5xx | 服务端错误 | Warning（可能临时故障） |

> ⚠️ **403 处理说明**：403 不直接判定为 Error，因为许多代码托管平台（如 Gitee）对未登录用户返回 403，但链接本身是有效的。仅当模式匹配确认域名为已知代码托管平台且状态码为 403 时，降级为 Warning 而非 Error。

## 代码托管平台 raw 链接转换

GitCode/AtomGit 的 `blob` 链接转为 `raw` 链接再请求：
- `https://{domain}/{org}/{repo}/blob/{branch}/{file}` → `https://raw.{domain}/{org}/{repo}/raw/{branch}/{file}`
